# Phase 2 Security and Access Model

## Agent identity
Each agent setup package generated by `/setup_agent` contains:

- a unique `agent_id`
- a unique bearer token
- a unique Windows service name

The bot stores the agent as `pending_activation` until the owner runs `/activate_agent`.

## Why not one shared package?
The base code is the same, but every generated setup ZIP has a different token. This prevents one leaked token from controlling all servers.

## Access model
Phase 2 starts with agent ownership:

- The Telegram user who runs `/setup_agent` becomes owner.
- The owner can activate and use the agent.
- The package includes `/agent_users` to show the current role mapping.

Planned next extension:

- Owner
- Manager
- Member
- invite codes
- role promotion/demotion

## Network security note
For LAN testing, HTTP is acceptable. For production, use VPN, HTTPS, or an outbound agent model so bearer tokens are not exposed on open networks.
