# Phase 2.5 Cloudflare-ready test guide

This build is prepared for the Phase 2.5 architecture:

```text
Telegram bot -> Backend job queue <- Outbound agent
```

The bot and agent no longer need direct bot-to-agent networking. For this test, the backend can run locally on the old laptop and be exposed through Cloudflare Tunnel.

## What changed in this build

- Persistent Telegram bottom menu was added.
- Menu buttons now execute actions such as Deploy, My Agents, Status, Logs, History, and Help.
- Backend job/deployment history was added.
- New `/history [agent_id]` command shows recent jobs for each agent.
- Backend has `/api/bot/agents/<agent_id>/history` and `/api/bot/jobs` endpoints.
- Outbound agent polling bug was fixed so the agent correctly picks up pending backend jobs.
- `backend.public_url` was added to `config/settings.json`.
- Agent packages generated by `/setup_agent` use the public backend URL, which is useful for Cloudflare Tunnel.

## Old laptop setup

Extract this package to:

```text
C:\CICD_25
```

Create venv and install requirements:

```cmd
cd C:\CICD_25
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Edit:

```text
C:\CICD_25\config\settings.json
```

Set your Telegram token.

Keep backend local URL as:

```json
"base_url": "http://127.0.0.1:9000"
```

After starting Cloudflare Tunnel, set:

```json
"public_url": "https://YOUR-TUNNEL.trycloudflare.com"
```

The bot uses `base_url` for local backend access. Generated outbound agent packages use `public_url`.

## Start backend

```cmd
cd C:\CICD_25
.venv\Scripts\activate.bat
python -u -m backend.main
```

Test locally:

```cmd
curl -i http://127.0.0.1:9000/api/health
```

## Start Cloudflare Tunnel

In another CMD:

```cmd
cloudflared tunnel --url http://127.0.0.1:9000
```

Copy the generated HTTPS URL and put it in `backend.public_url` in `config/settings.json`.

## Start bot

Restart the bot after editing `settings.json`:

```cmd
cd C:\CICD_25
.venv\Scripts\activate.bat
python -u -m bot.main
```

In Telegram:

```text
/backend_status
```

It should show both:

- local backend URL
- agent/public backend URL

## Generate outbound agent package

In Telegram:

```text
/setup_agent Main-Outbound-Agent
```

The generated package should show the Cloudflare URL as backend.

Download that ZIP on the IIS/main laptop.

## Install outbound agent on main laptop

Extract to:

```text
C:\CICD_AGENT_25
```

Open:

```text
C:\CICD_AGENT_25\config\settings.json
```

Confirm:

```json
"mode": "outbound",
"backend_url": "https://YOUR-TUNNEL.trycloudflare.com"
```

Then right-click:

```text
scripts\install_agent_service.bat
```

Choose **Run as Administrator**.

The outbound agent does not need the bot laptop to reach port 8765.

## Check agent status

In Telegram:

```text
/myagents
/status
```

The status should show a recent heartbeat through the backend.

## Deploy

Use `/deploy` or the 🚀 Deploy button.

Use:

```text
Site: DemoSite25
Port: 8087
App pool: DemoPool25
Health URL: http://127.0.0.1:8087/index.html
```

Expected flow:

```text
Bot uploads ZIP to backend.
Backend creates job.
Outbound agent polls backend.
Agent downloads package.
Agent deploys to IIS.
Agent reports result.
Bot shows result.
```

## Check history

After deployment:

```text
/history
```

This should show recent jobs for the current agent, including status, site, app pool, job ID, release ID, user, and summary.

## Notes

- Cloudflare temporary tunnel URLs change when restarted.
- If the URL changes, update `backend.public_url`, restart the bot, and generate a new agent package.
- For final product architecture, the backend should be hosted on a real server with HTTPS, persistent database, and stronger production settings.
